# Подходы к задаче "Security System"

## Суть задачи

Дано изображение размера N×M из нулей и единиц.
Также дано K контрольных элементов, каждый является квадратом L×L из нулей и единиц.
Нужно для каждого контрольного элемента посчитать, сколько раз он встречается в изображении как окно L×L.
Повороты и отражения запрещены, поэтому окно должно совпадать с элементом точно.
Например, элемент из одних единиц встречается столько раз, сколько в изображении квадратов L×L из единиц.

## Подходы

### 1. Bruteforce

#### Идея bruteforce

Проверить каждое окно изображения для каждого контрольного элемента.

#### Как работает bruteforce

Для элемента с номером p перебираются все возможные левые верхние углы окна: строка i от 0 до N-L и столбец j от 0 до M-L.
Для каждой позиции (i, j) выполняется сравнение всех L строк окна с L строками элемента.
Если очередная строка окна `image[i+x][j:j+L]` не равна строке элемента `patterns[p][x]`, сравнение прерывается.
Если все L строк совпали, счётчик `ans[p]` увеличивается на единицу.
Такой перебор повторяется для всех K элементов.

#### Сложность bruteforce

Число положений окна равно O(N*M), каждое сравнение занимает O(L^2).
Для K элементов итоговое время - O(K*N*M*L^2).
Дополнительная память - O(K*L^2) на хранение самих элементов.

### 2. 2D rolling hash

#### Идея 2D rolling hash

Заменить сравнение квадратов L×L сравнением двух 64-битных хешей.

#### Как работает 2D rolling hash

Хеш квадрата строится по двум основаниям: P для строк и Q для столбцов.
Сначала для каждого контрольного элемента вычисляется пара хешей `patternHash`.
Хеш элемента собирается сверху вниз: строка читается слева направо по основанию Q, затем результат добавляется по основанию P.
Далее изображение обрабатывается построчно, и для каждого столбца поддерживается вертикальный хеш окна из L строк в массиве `v1`.
При добавлении новой строки выполняется `v1[c] = v1[c]*P + bit`, а при выходе старой строки из окна вычитается `bit*P^L`.
Когда окно из L строк готово, по массиву `v1` скользящим окном ширины L считается горизонтальный хеш `h1`.
Горизонтальный хеш обновляется как `h1 = h1*Q + v1[c]` с вычитанием `v1[c-L]*Q^L` при сдвиге.
Пара `hashKey{h1, h2}` ищется в хеш-таблице `patternIndex`, и счётчики найденных элементов увеличиваются.
Две независимые пары оснований снижают вероятность ложного совпадения до примерно 2^-128.

#### Сложность 2D rolling hash

Каждая клетка изображения обрабатывается за O(1), всего клеток N*M.
Построение хешей K элементов занимает O(K*L^2).
Итоговое время - O(N*M + K*L^2), дополнительная память - O(M + K*L^2) без учёта хранения изображения.

## Сравнение подходов

| Подход          | Время                | Память       | Коллизии     | Сложность кода |
|-----------------|----------------------|--------------|--------------|----------------|
| Bruteforce      | O(K*N*M*L^2)         | O(K*L^2)     | нет          | низкая         |
| 2D rolling hash | O(N*M + K*L^2)       | O(M + K*L^2) | около 2^-128 | высокая        |

## Что выбрать

- Для больших изображений выбирайте 2D rolling hash, потому что он обрабатывает каждую клетку один раз.
- Для маленьких изображений и простой проверки подойдёт bruteforce.
- Если нужна полная гарантия без коллизий, используйте прямое сравнение или дополнительную проверку хешей.
