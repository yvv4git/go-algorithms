# Подходы к задаче "Comparing Subtrees"

## Суть задачи

Дано дерево с корнем в вершине 1, и каждой вершине приписано число.
Корневое поддерево вершины v - это сама вершина v и все её потомки.
Нужно посчитать количество пар различных вершин, корневые поддеревья которых изоморфны.
Изоморфизм сохраняет значения вершин, корень и связи между вершинами, а порядок детей не важен.
Например, два листа с одинаковым значением всегда образуют одну изоморфную пару.

## Подходы

### 1. Bruteforce

#### Идея bruteforce

Построить для каждого поддерева строковую сигнатуру и сравнить все пары сигнатур.

#### Как работает bruteforce

Сначала дерево обходится от корня, чтобы для каждой вершины получить список детей.
Затем вершины обрабатываются в обратном порядке обхода, то есть дети раньше родителей.
Для вершины v сигнатура строится так: берутся сигнатуры всех детей, сортируются как строки и склеиваются через запятую.
К ним спереди добавляется значение вершины, например `2(2(),2())`.
После построения всех сигнатур двойной цикл сравнивает каждую пару вершин i < j.
Если сигнатуры совпали, поддеревья изоморфны и счётчик увеличивается на единицу.

#### Сложность bruteforce

В цепочке длина сигнатуры растёт вместе с глубиной, поэтому суммарный размер сигнатур достигает O(n^2).
Сравнение всех пар добавляет O(n^2) сравнений строк.
Итоговое время - O(n^3) в худшем случае, память - O(n^2) в худшем случае.

### 2. Canonical IDs

#### Идея canonical IDs

Заменить длинные строковые сигнатуры короткими целыми идентификаторами.

#### Как работает canonical IDs

Вершины обрабатываются в обратном порядке обхода, поэтому идентификаторы детей уже известны.
Для вершины v собираются идентификаторы всех детей, сортируются по возрастанию и превращаются в ключ вместе со значением v.
Хеш-таблица typeMap хранит соответствие "ключ -> идентификатор".
Если такой ключ уже встречался, вершина получает существующий идентификатор, иначе ей выдаётся новый.
Так одинаковые по структуре поддеревья получают одинаковый идентификатор, а разные - разный.
После обработки всех вершин остаётся посчитать частоты идентификаторов: форма с частотой cnt даёт cnt*(cnt-1)/2 пар.

#### Сложность canonical IDs

Сортировка списков детей по всем вершинам занимает O(n*log n) в худшем случае.
Суммарная длина всех ключей равна O(n), потому что каждый ребро добавляет один идентификатор ребёнка.
Итоговое время - O(n*log n), память - O(n).

### 3. Subtree hash

#### Идея subtree hash

Считать для каждого поддерева две 64-битные хеш-суммы вместо строковых ключей.

#### Как работает subtree hash

Вершины обрабатываются в обратном порядке обхода, как и в предыдущем подходе.
Для вершины v собираются пары хешей всех детей и сортируются лексикографически по двум компонентам.
Начальные значения h1 и h2 получаются перемешиванием значения вершины функцией mix64 с разными seed.
Затем для каждого ребёнка выполняется h1 = h1*baseOne + childH1 и h2 = h2*baseTwo + childH2.
Порядок детей фиксирован сортировкой, поэтому одинаковые поддеревья дают одинаковую пару хешей.
Хеш-таблица хранит частоты пар, а ответ складывается из cnt*(cnt-1)/2 по всем парам.
Разные поддеревья могут случайно получить одинаковую пару хешей, вероятность около 2^-128.

#### Сложность subtree hash

Сортировка списков детей по всем вершинам занимает O(n*log n) в худшем случае.
Вычисление хешей и подсчёт частот занимают O(n) в среднем.
Итоговое время - O(n*log n) в среднем, память - O(n).

## Сравнение подходов

| Подход        | Время          | Память | Коллизии     | Сложность кода |
|---------------|----------------|--------|--------------|----------------|
| Bruteforce    | O(n^3)         | O(n^2) | нет          | низкая         |
| Canonical IDs | O(n*log n)     | O(n)   | нет          | средняя        |
| Subtree hash  | O(n*log n)     | O(n)   | около 2^-128 | средняя        |

## Что выбрать

- Для точного решения без риска коллизий выбирайте canonical IDs.
- Для максимальной скорости на больших деревьях выбирайте subtree hash с двумя 64-битными суммами.
- Bruteforce подходит только для маленьких деревьев, потому что хранит длинные строки и сравнивает все пары.
