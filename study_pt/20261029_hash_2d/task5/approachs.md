# Подходы к задаче "Nice Rectangles"

## Суть задачи

Дана картина размера N×M, каждая клетка которой покрашена одной из 26 букв.
Часть картины - это любой прямоугольник, вырезанный по границам клеток.
Часть называется симпатичной, если при повороте на 180 градусов вокруг своего центра раскраска не меняется.
Нужно посчитать количество всех симпатичных частей.
Например, любая часть из одной клетки всегда симпатична, а часть 2×2 симпатична только при совпадении противоположных клеток.

## Подходы

### 1. Bruteforce

#### Идея bruteforce

Перебрать все прямоугольники и проверить симметрию каждой клетки.

#### Как работает bruteforce

Часть задаётся четырьмя границами: r1, r2, c1, c2.
Для каждой такой части перебираются все её клетки (r, c).
Симметричная клетка имеет координаты (r1+r2-r, c1+c2-c), и её цвет должен совпадать с цветом клетки (r, c).
Если хотя бы одна пара не совпала, часть не считается симпатичной и проверка прерывается.
Если все пары совпали, счётчик `ans` увеличивается на единицу.
Так перебираются все O(N^2*M^2) прямоугольников.

#### Сложность bruteforce

Число прямоугольников равно O(N^2*M^2), проверка одного прямоугольника занимает O(N*M) в худшем случае.
Итоговое время - O(N^3*M^3).
Дополнительная память - O(1).

### 2. 2D prefix hash

#### Идея 2D prefix hash

Сравнивать прямоугольники по 2D хешу за O(1) вместо посимвольного сравнения.

#### Как работает 2D prefix hash

Строится префиксный хеш `pref[i][j]` для верхнего левого угла (0, 0) и прямоугольника до (i-1, j-1).
Хеш учитывает строки с основанием P и столбцы с основанием Q, а также степени этих оснований в массивах `powP` и `powQ`.
Хеш произвольного прямоугольника получается включением-исключением из четырёх значений `pref` за O(1).
Далее строится такой же префиксный хеш для повёрнутого изображения, где клетка (i, j) равна `grid[N-1-i][M-1-j]`.
Для исходной части с границами (r1, r2, c1, c2) повёрнутая часть имеет границы (N-1-r2, N-1-r1, M-1-c2, M-1-c1).
Если хеши этих двух прямоугольников совпали, часть симпатична.
Используются две независимые пары оснований, чтобы вероятность ложного совпадения была около 2^-128.

#### Сложность 2D prefix hash

Перебор всех прямоугольников занимает O(N^2*M^2), а хеш каждого прямоугольника считается за O(1).
Построение префиксных хешей занимает O(N*M).
Итоговое время - O(N^2*M^2), память - O(N*M).

## Сравнение подходов

| Подход          | Время         | Память | Коллизии     | Сложность кода |
|-----------------|---------------|--------|--------------|----------------|
| Bruteforce      | O(N^3*M^3)    | O(1)   | нет          | низкая         |
| 2D prefix hash  | O(N^2*M^2)    | O(N*M) | около 2^-128 | средняя        |

## Что выбрать

- Для ограничений N, M <= 100 выбирайте 2D prefix hash, потому что он укладывается в лимит времени.
- Bruteforce подходит только для совсем маленьких картин.
- Если нужна полная гарантия без коллизий, сравнивайте клетки напрямую или перепроверяйте совпадения хешей.
