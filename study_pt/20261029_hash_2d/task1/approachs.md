# Подходы к задаче "Count Distinct Sets"

## Суть задачи

Дано N множеств, в каждом по K различных целых чисел.
Множество не зависит от порядка элементов, поэтому `1 2 3` и `3 2 1` - это одно и то же множество.
Нужно посчитать, сколько различных множеств встречается в наборе.
Например, среди наборов `1 2 3`, `3 2 1`, `11 12 13`, `2 1 3` есть только два различных множества.

## Подходы

### 1. Bruteforce

#### Идея bruteforce

Сравнивать каждое новое множество со всеми уже встреченными.

#### Как работает bruteforce

Сначала каждое множество сортируется по возрастанию, чтобы порядок элементов перестал иметь значение.
Затем для множества с номером i выполняется проход по всем множествам с номерами от 0 до i-1.
Если найден полностью совпадающий отсортированный массив, множество считается повторным и не увеличивает ответ.
Если совпадений нет, счётчик различных множеств увеличивается на единицу.

#### Сложность bruteforce

Сортировка всех множеств занимает O(N*K*log K).
Сравнение всех пар множеств занимает O(N^2*K).
Итоговое время - O(N^2*K), память - O(N*K).

### 2. Sort and hash

#### Идея sort and hash

Хранить канонические представления уже встреченных множеств в хеш-таблице.

#### Как работает sort and hash

Каждое множество копируется и сортируется по возрастанию.
Отсортированные числа записываются в строку через запятую, например `1,2,3,`.
Такой строковый ключ однозначно задаёт множество, потому что числа неотрицательные и разделитель всегда один.
Ключ добавляется в `map[string]struct{}` с именем `seen`.
Количество элементов в `seen` после обработки всех строк и есть ответ.
Хеш-таблица сравнивает ключи точно, поэтому ложных совпадений здесь нет.

#### Сложность sort and hash

Сортировка каждого из N множеств длины K занимает O(N*K*log K).
Построение ключей и вставка в хеш-таблицу занимают O(N*K) в среднем.
Итоговое время - O(N*K*log K), память - O(N*K).

### 3. Set hash

#### Идея set hash

Считать для множества хеш, который не зависит от порядка элементов.

#### Как работает set hash

Для каждого значения v вычисляются две псевдослучайные 64-битные величины `mix64(v + seed1)` и `mix64(v + seed2)`.
Суммы этих величин по всем элементам множества не меняются при перестановке элементов.
Поэтому одинаковые множества дают одинаковую пару сумм `h1` и `h2`.
Пара `[2]uint64{h1, h2}` используется как ключ в таблице `seen`.
Разные множества могут случайно дать одинаковую пару, но вероятность такого события около 2^-128.
Если нужна полная гарантия без коллизий, лучше выбрать подход sort and hash.

#### Сложность set hash

Обработка всех N*K элементов занимает O(N*K) в среднем.
Вставка в хеш-таблицу и подсчёт ключей занимают O(N) в среднем.
Итоговое время - O(N*K) в среднем, память - O(N).

## Сравнение подходов

| Подход        | Время           | Память | Коллизии      | Сложность кода |
|---------------|-----------------|--------|---------------|----------------|
| Bruteforce    | O(N^2*K)        | O(N*K) | нет           | низкая         |
| Sort and hash | O(N*K*log K)    | O(N*K) | нет           | низкая         |
| Set hash      | O(N*K) в среднем| O(N)   | около 2^-128  | средняя        |

## Что выбрать

- Для надёжного решения без риска коллизий выбирайте sort and hash.
- Для максимальной скорости на больших входах выбирайте set hash с двумя 64-битными суммами.
- Bruteforce подходит только для маленьких N, потому что его время квадратично по N.
