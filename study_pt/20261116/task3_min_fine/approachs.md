# Подходы к задаче "Deadlines"

## Суть задачи

Вася решает ровно одну задачу в день.
У каждой задачи есть дедлайн - номер дня, до которого включительно её нужно решить.
Если задачу с дедлайном t решить в день d, то штраф за неё равен max(0, d - t).
Нужно назначить каждой задаче свой день от 1 до N так, чтобы суммарный штраф был минимальным.
Ключевая идея: задачи выгодно решать в порядке возрастания дедлайна.
Это правило называют EDD (Earliest Due Date, самый ранний дедлайн первым).

## Подходы

### 1. Naive selection

#### Идея naive selection

Каждый день среди ещё не решённых задач выбирать ту, у которой самый маленький дедлайн.
Дедлайн - это крайний день, когда задачу ещё можно решить без штрафа.

#### Как работает naive selection

Задачи хранятся в массиве deadlines, где deadlines[i] - дедлайн задачи с номером i.
Массив solved помечает уже решённые задачи, а массив answer хранит назначенный день для каждой задачи.
Дни идут по порядку от 1 до N, и на каждый день выбирается ровно одна задача.

Возьмём пример с дедлайнами 2, 3, 1 для задач 1, 2, 3.

Шаг 1. День 1: не решены все три задачи, минимальный дедлайн 1 у задачи 3.
Назначаем задаче 3 день 1.

```text
Задачи:      1(t=2)   2(t=3)   3(t=1)
День 1:      -        -        выбрана, t=1 -> день 1
Остались:    1(t=2)   2(t=3)
```

Шаг 2. День 2: остались задачи 1 и 2, минимальный дедлайн 2 у задачи 1.
Назначаем задаче 1 день 2.

```text
День 2:      выбрана, t=2 -> день 2
Остались:    2(t=3)
```

Шаг 3. День 3: осталась задача 2, назначаем ей день 3.

```text
День 3:      выбрана, t=3 -> день 3
Ответ по номерам задач: 2 3 1
```

Почему выбор минимального дедлайна оптимален, покажем обменом.
Пусть две задачи с дедлайнами 5 и 2 стоят на днях 2 и 3.
Если сначала решить задачу с дедлайном 5, штрафы равны max(0, 2-5) = 0 и max(0, 3-2) = 1, всего 1.
Если сначала решить задачу с дедлайном 2, штрафы равны max(0, 2-2) = 0 и max(0, 3-5) = 0, всего 0.
Значит, задачу с меньшим дедлайном выгодно ставить раньше.
Повторяя такой обмен, любое расписание можно привести к порядку возрастания дедлайна, не увеличив штраф.

#### Сложность naive selection

Каждый из N дней просматривает до N нерешённых задач, это O(N^2) времени.
Массивы solved и answer занимают O(N) памяти.

### 2. Greedy EDD

#### Идея greedy EDD

Один раз отсортировать задачи по возрастанию дедлайна и назначить дни 1..N в этом порядке.
EDD расшифровывается как Earliest Due Date, то есть самый ранний дедлайн первым.

#### Как работает greedy EDD

Создадим массив номеров задач order = [0, 1, ..., N-1] и отсортируем его по deadlines.
Задача на позиции k в отсортированном порядке получает день k+1.
Дни 1..N выдаются подряд, поэтому каждая задача получает свой уникальный день.

Продолжим пример с дедлайнами 2, 3, 1.
После сортировки по дедлайну порядок задач такой: 3 (t=1), 1 (t=2), 2 (t=3).

```text
Позиция:    1        2        3
Задача:     3        1        2
Дедлайн:    1        2        3
День:       1        2        3
```

Остаётся разложить дни по исходным номерам задач.
Задача 3 получает день 1, задача 1 - день 2, задача 2 - день 3.
В порядке ввода ответ равен 2 3 1.

Почему это оптимально, объясняет тот же обмен, что и в naive selection.
Задача с меньшим дедлайном всегда стоит не позже задачи с большим дедлайном, поэтому обменов не требуется.
Если дедлайны равны, порядок задач между собой не важен: штраф от этого не меняется.

#### Сложность greedy EDD

Сортировка N задач занимает O(N log N) времени.
Массивы order и answer занимают O(N) памяти.

## Сравнение подходов

| Подход          | Время      | Память | Коллизии | Сложность кода |
|-----------------|------------|--------|----------|----------------|
| Naive selection | O(N^2)     | O(N)   | нет      | низкая         |
| Greedy EDD      | O(N log N) | O(N)   | нет      | низкая         |

## Что выбрать

- Greedy EDD - основное решение: одна сортировка сразу даёт оптимальный порядок.
- Naive selection проще для понимания и при N <= 100 тоже укладывается в лимит времени.
- Оба подхода дают минимальный штраф, поэтому для ответа подходит любой из них.
