# Подходы к задаче "Large Square"

## Суть задачи

Город - прямоугольник N x M с вертикальными и горизонтальными улицами.
Улица - это линия нулевой ширины: вертикальная стоит на координате x, горизонтальная - на координате y.
Нужно купить квадратный участок, который не пересекает улицы и целиком лежит в городе, и найти максимальную сторону такого квадрата.
Ключевая идея: квадрат помещается в ячейку между соседними улицами.
Сторона квадрата равна min(максимальный зазор по x, максимальный зазор по y).

## Подходы

### 1. Sort gaps

#### Идея sort gaps

Отсортировать координаты улиц, добавить границы города и найти самый широкий промежуток между соседними линиями по каждой оси.

#### Как работает sort gaps

Ячейка - это прямоугольник между двумя соседними вертикальными улицами и двумя соседними горизонтальными.
Границы города x = 0, x = N, y = 0 и y = M участвуют в разбиении на ячейки наравне с улицами.
Возьмём пример N = 10, M = 10, вертикальная улица x = 3, горизонтальная y = 5.

Шаг 1. Собираем координаты по x: улицы и обе границы, получаем 0, 3, 10.
Шаг 2. Считаем зазоры между соседними значениями: 3 - 0 = 3 и 10 - 3 = 7.
Шаг 3. Максимальный зазор по x равен maxX = 7.

```text
x: 0    3         10
   +----+---------+
   | 3  |    7    |   зазоры по x
   +----+---------+
```

Шаг 4. Повторяем то же самое по y: координаты 0, 5, 10, зазоры 5 и 5, maxY = 5.

```text
y: 0    5    10
   +----+----+
   | 5  | 5  |      зазоры по y
   +----+----+
```

Шаг 5. Квадрат должен поместиться в одной ячейке, поэтому его сторона не превышает ни maxX, ни maxY.
Ответ равен min(maxX, maxY) = min(7, 5) = 5.

Улицы могут стоять на границе города, например x = 0.
Тогда зазор рядом с ней равен 0, и он просто не становится максимальным.
Порядок улиц на входе не важен, потому что координаты всё равно сортируются.

#### Сложность sort gaps

Сортировка вертикальных и горизонтальных координат занимает O(Vert*log Vert) + O(Hor*log Hor).
Один проход по отсортированным массивам для зазоров занимает O(Vert + Hor).
Итоговое время - O((Vert+Hor)*log(Vert+Hor)), память - O(Vert + Hor).

### 2. Binary search

#### Идея binary search

Бинарно искать ответ k: для каждого k проверять, есть ли по x и по y промежуток длины не меньше k.

#### Как работает binary search

Бинарный поиск - это метод, который за O(log L) итераций находит границу между подходящими и неподходящими значениями.
Сначала отсортируем координаты улиц и добавим границы - так же, как в подходе sort gaps.
Затем ищем ответ k в диапазоне от 0 до min(N, M).

Проверка для фиксированного k выглядит так.
По x пройдем по отсортированным координатам и найдем, есть ли соседняя пара с разностью не меньше k.
Если такая пара есть, условие по x выполняется, иначе нет.
То же самое проверяем по y.
Если обе проверки прошли, k достигимо, и пробуем больший k.
Если хотя бы одна проверка провалилась, k слишком велико, и берём меньший k.

Работает проверка на примере N = 10, M = 10, x = 3, y = 5 при k = 5.
По x зазоры 3 и 7, есть зазор 7 >= 5, проверка по x прошла.
По y зазоры 5 и 5, есть зазор 5 >= 5, проверка по y прошла.
Значит, k = 5 достигимо, и ответ не меньше 5.
При k = 6 по y зазоры 5 и 5, все меньше 6, проверка провалилась, ответ меньше 6.
Итоговый ответ равен 5.

#### Сложность binary search

Сортировка занимает O((Vert+Hor)*log(Vert+Hor)).
Бинарный поиск выполняет O(log min(N, M)) итераций, каждая проверка - O(Vert + Hor).
Итоговое время - O((Vert+Hor)*log(Vert+Hor) + log(min(N,M))*(Vert+Hor)), память - O(Vert + Hor).

## Сравнение подходов

| Подход        | Время                                           | Память        | Коллизии | Сложность кода |
|---------------|-------------------------------------------------|---------------|----------|----------------|
| Sort gaps     | O((Vert+Hor)*log(Vert+Hor))                     | O(Vert + Hor) | нет      | низкая         |
| Binary search | O((Vert+Hor)*log(Vert+Hor)+log(min(N,M))*(V+H)) | O(Vert + Hor) | нет      | средняя        |

## Что выбрать

- Sort gaps является основным решением: один проход после сортировки даёт ответ сразу.
- Binary search подходит, когда проверка "помещается ли k" приходит отдельно от формулы min(maxX, maxY).
- Оба подхода укладываются в лимиты: Vert и Hor не больше 100000, координаты до 10^9.
