# Подходы к задаче "Physical Buttons"

## Суть задачи

Дано N эмодзи с частотами a_1, ..., a_N в фиксированном порядке и M кнопок.
Эмодзи нужно разложить по кнопкам подряд: несколько первых на первую кнопку, следующие на вторую и так далее.
Если на кнопке лежат k эмодзи по порядку, то выбор j-го из них стоит j нажатий, а вклад кнопки равен a_{p+1} + 2*a_{p+2} + ... + k*a_{p+k}.
Нужно найти разбиение на M групп подряд с минимальной суммой нажатий и вывести размеры групп b_1, ..., b_M.

## Подходы

### 1. Bruteforce (полный перебор разбиений)

#### Идея перебора

Попробовать все способы поставить M-1 границу между N эмодзи и выбрать разбиение с минимальной стоимостью.

#### Как работает перебор

Разбиение на M групп подряд определяется размерами b_1, ..., b_M, где b_i >= 0 и b_1 + ... + b_M = N.
Рекурсивно выбираем размер первой группы, затем второй и так далее, пока не распределим все эмодзи по всем кнопкам.
Для каждого полного разбиения считаем стоимость: для группы размера k прибавляем a_{p+1} + 2*a_{p+2} + ... + k*a_{p+k}.
Запоминаем разбиение с наименьшей суммой и выводим его.

Например, для частот 1, 3, 5, 1, 1 и M = 3 перебор проверит, среди прочих, вариант (1, 1, 3).
Его стоимость 1*1 + 3*1 + 5*1 + 1*2 + 1*3 = 14, и это оптимальный ответ.

#### Сложность перебора

Время O(C(N+M-1, M-1) * N), память O(N + M).

### 2. Dynamic programming (динамическое программирование)

#### Идея динамического программирования

Строить ответ слева направо, запоминая лучшую стоимость для первых i эмодзи, размещённых на j кнопках.

#### Как работает динамическое программирование

Пусть `dp[j][i]` - минимальная стоимость, если первые `i` эмодзи распределены по первым `j` кнопкам.
Тогда последняя, `j`-я кнопка содержит некоторый хвост из `k` эмодзи: `i-k+1, ..., i`.
Переход: `dp[j][i] = min(dp[j-1][i-k] + cost(i-k+1, i))` по всем допустимым `k`, где `cost(l, r) = a_l + 2*a_{l+1} + ... + (r-l+1)*a_r`.
База: `dp[0][0] = 0`, остальные значения считаются бесконечностью.
Ответ лежит в `dp[M][N]`.

Чтобы вывести `b_i`, храним выбор `k` для каждого состояния в массиве `prev[j][i]`.
После нахождения ответа идём назад от `(M, N)` к `(0, 0)` и восстанавливаем размеры групп.

Например, для 1, 3, 5, 1, 1 оптимально получить `dp[1][1]` из группы (1), `dp[2][2]` из группы (3), `dp[3][5]` из группы (5, 1, 1).

#### Сложность динамического программирования

Время `O(N^2*M)`, память `O(N*M)`.

## Сравнение подходов

| Подход                        | Время                 | Память   | Точность | Сложность кода |
|-------------------------------|-----------------------|----------|----------|----------------|
| Полный перебор разбиений      | $O(C(N+M-1,M-1) * N)$ | $O(N+M)$ | Точная   | Низкая         |
| Динамическое программирование | $O(N^2*M)$            | $O(N*M)$ | Точная   | Средняя        |

## Что выбрать

- При N <= 30 и M <= 10 полный перебор уже проходит, но число вариантов растёт быстро.
- Динамическое программирование даёт гарантированно быстрый и детерминированный ответ.
- Для восстановления размеров кнопок удобно хранить таблицу предыдущих выборов.
