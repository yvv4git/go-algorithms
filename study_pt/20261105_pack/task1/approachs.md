# Подходы к задаче "Correcting One Error"

## Суть задачи

Программа запускается дважды.
При первом запуске она получает строку x и выдаёт строку y с избыточными битами.
Жюри меняет в y не более одного бита и получает строку z.
При втором запуске программа получает z и должна восстановить исходную строку x.
Формально нужно построить код, исправляющий одну ошибку, длина которого не превосходит m.
Число m не известно программе, но m не должно превышать n более чем на ceil(log2 n).

## Подходы

### 1. Repetition code

#### Идея repetition code

Записать каждый бит исходной строки несколько раз, чтобы ошибку можно было исправить голосованием большинства.

#### Как работает repetition code

Каждый бит строки x повторяется три раза: ноль превращается в 000, а единица - в 111.
Длина строки y получается равной 3n.
При втором запуске строка z разбивается на тройки.
В каждой тройке выбирается тот бит, который встречается чаще: если в тройке две единицы, восстанавливается 1, иначе 0.
Одна испорченная позиция меняет только одну тройку, поэтому большинство в ней остаётся верным.
Этот подход простой, но длина 3n превышает предел m, поэтому для сдачи задачи он не подходит.

#### Сложность repetition code

Кодирование и декодирование выполняются за один проход по строке, время O(n).
Память под строки y и z равна O(n).

### 2. Hamming code

#### Идея hamming code

Добавить к данным ровно столько контрольных битов, чтобы их синдром однозначно указывал номер испорченной позиции.

#### Как работает hamming code

Представь, что каждый бит строки лежит в ячейке с номером, как квартира в доме.
Если одна ячейка испортилась, нам нужно узнать её номер, чтобы починить именно её.
Для этого добавим несколько контрольных битов: они не хранят данные, а только помогают вычислить номер поломки.
Чётность - это ответ на вопрос, чётное или нечётное число единиц находится в группе ячеек.
Синдром - это число, собранное из ответов проверок, и оно равно номеру испорченной ячейки.

Сначала выберем число контрольных битов r.
Нужно, чтобы номеров хватило на все позиции и на случай "ошибки нет".
Поэтому требуем 2^r >= n + r + 1, где n + r - общая длина строки y.
Например, для n = 4 берём r = 3, потому что 2^3 = 8 >= 4 + 3 + 1 = 8.
Тогда в строке y будет 4 + 3 = 7 позиций.

Теперь пронумеруем позиции от 1 до 7.
Позиции 1, 2, 4 отдадим контрольным битам, потому что это степени двойки.
Остальные позиции 3, 5, 6, 7 займём битами строки x.
Для x = "1010" получается такая заготовка:

```text
Позиция:  1 2 3 4 5 6 7
Роль:     к к д к д д д
Бит:      ? ? 1 ? 0 1 0
```

Здесь "к" - контрольный бит, "д" - бит данных, а "?" пока не заполнен.

Каждый номер позиции можно записать в двоичной системе, например 5 - это 101.
Первая проверка смотрит на последнюю цифру номера.
Вторая проверка смотрит на среднюю цифру номера.
Третья проверка смотрит на первую цифру номера.
Если нужная цифра равна 1, позиция входит в группу этой проверки.
Получаются три группы:

- Первая проверка: позиции 1, 3, 5, 7.
- Вторая проверка: позиции 2, 3, 6, 7.
- Третья проверка: позиции 4, 5, 6, 7.

В каждой группе есть ровно один контрольный бит, поэтому его можно вычислить по остальным битам.
Контрольный бит ставится так, чтобы число единиц в его группе стало чётным.
Сначала считаем единицы среди битов данных этой группы.
Если единиц нечётное число, контрольный бит ставим в 1, иначе в 0.
Для нашего примера:

| Группа | Позиции данных | Единицы | Чётность | Контрольный бит |
|--------|----------------|---------|----------|-----------------|
| 1      | 3, 5, 7        | 3       | нечётная | 1               |
| 2      | 3, 6, 7        | 3, 6    | чётная   | 0               |
| 4      | 5, 6, 7        | 6       | нечётная | 1               |

Получаем y = "1011010":

```text
Позиция:  1 2 3 4 5 6 7
Бит:      1 0 1 1 0 1 0
```

Теперь представим, что жюри испортило позицию 5 и заменило 0 на 1.
Строка z выглядит так:

```text
Позиция:  1 2 3 4 5 6 7
Бит:      1 0 1 1 1 1 0
```

Декодер снова считает чётность каждой группы, но теперь вместе с контрольным битом.
Если число единиц нечётное, проверка даёт 1, а если чётное - 0.
Получаются три ответа:

| Проверка | Позиции    | Единицы | Ответ |
|----------|------------|---------|-------|
| 1        | 1, 3, 5, 7 | 1, 3, 5 | 1     |
| 2        | 2, 3, 6, 7 | 3, 6    | 0     |
| 4        | 4, 5, 6, 7 | 4, 5, 6 | 1     |

Собираем ответы в синдром: проверка 4 даёт старший бит, проверка 2 - средний, проверка 1 - младший.
Получается двоичное число 101, то есть 5.
Значит, испорчена позиция 5, и декодер меняет её обратно.
После этого он выбрасывает контрольные позиции 1, 2, 4 и читает данные в позициях 3, 5, 6, 7.
Получается 1, 0, 1, 0, то есть исходная строка x = "1010".
Если бы все три проверки дали 0, синдром был бы равен 0, и декодер решил бы, что ошибки нет.

Почему номер поломки всегда находится правильно?
У каждой позиции от 1 до 7 есть свой уникальный трёхбитный номер.
Ошибка в позиции p переворачивает ровно те проверки, где в номере p стоит единица.
Поэтому синдром в точности равен p, и никакая другая позиция дать такой же синдром не может.

#### Сложность hamming code

Кодирование и декодирование выполняются за O(n * r), где r = O(log n), то есть O(n log n).
На практике r не превосходит 17, поэтому время близко к O(n).
Память под строки y и z равна O(n).

## Сравнение подходов

| Подход          | Время      | Память | Коллизии | Сложность кода |
|-----------------|------------|--------|----------|----------------|
| Repetition code | O(n)       | O(n)   | нет      | низкая         |
| Hamming code    | O(n log n) | O(n)   | нет      | средняя        |

## Что выбрать

- Repetition code подходит только для демонстрации идеи, потому что длина 3n нарушает предел m.
- Hamming code является основным решением: он укладывается в предел m и исправляет ровно одну ошибку.
- Для сдачи задачи используйте Hamming code.
