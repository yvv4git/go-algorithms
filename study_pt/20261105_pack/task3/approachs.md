# Подходы к задаче "Packing and Unpacking"

## Суть задачи

Программа запускается дважды и не может сохранить состояние между запусками.
При первом запуске (`pack`) она получает строку `s` из маленьких английских букв `a..z` и печатает `N` и `N` байт.
При втором запуске (`unpack`) она получает те же `N` байт и должна восстановить строку `s` символ в символ.
Главное ограничение: `N <= len(s) / 2`, то есть на одну букву в среднем не больше 4 бит.

Почему 4 бита?
Один байт - это 8 бит, а лимит разрешает потратить половину байта на букву.

```text
n букв, можно потратить n/2 байт
n/2 байт = (n/2) * 8 бит = 4 * n бит
значит на одну букву в среднем не больше 4 бит
```

Обычное кодирование каждой буквы отдельно даёт около 4.1-4.2 бита на букву, а это больше лимита.
Причина в том, что буквы в английском тексте зависят друг от друга.
После `q` почти всегда идёт `u`, а после `th` очень часто идёт `e`.
Если кодировать букву с учётом предыдущих, на неё нужно меньше бит.
Именно эту идею используют оба подхода ниже.

## Подходы

### 1. Arithmetic coding order 1 (арифметическое кодирование, контекст 1)

#### Идея arithmetic coding order 1

Представим всю строку как одно длинное число-дробь из отрезка `[0, 1)`.
Каждая следующая буква сужает этот отрезок и делает его всё уже.
В конце достаточно записать любое число из полученного отрезка, и декодер восстановит всю строку.
Вероятность буквы берётся с учётом одной предыдущей буквы, то есть из контекста порядка 1.
Модель адаптивная: вероятности не хранятся в файле, а обновляются по ходу одинаково у кодировщика и декодера.

#### Как работает arithmetic coding order 1

Сначала отрезок `[0, 1)` делится на 26 частей по числу букв.
Ширина каждой части пропорциональна частоте буквы в текущем контексте.
Чем чаще буква, тем шире её часть и тем меньше бит нужно, чтобы в неё попасть.

Разберём маленький пример с алфавитом из трёх букв `a`, `b`, `c`.
Пусть сначала все три буквы равновероятны, тогда части одинаковые.

```text
0                 1/3                2/3                1.0
+------------------+------------------+------------------+
|         a        |         b        |         c        |
+------------------+------------------+------------------+
```

Закодируем строку `cab` шаг за шагом.

```text
Шаг 0: текущий отрезок [0.000, 1.000), ширина 1.000
Шаг 1: буква c -> [0.667, 1.000), ширина 0.333
Шаг 2: буква a -> [0.667, 0.778), ширина 0.111
Шаг 3: буква b -> [0.704, 0.741), ширина 0.037
```

Каждый шаг выбирает внутри текущего отрезка часть, которая соответствует букве.
Например, на шаге 2 буква `a` занимает первую треть отрезка `[0.667, 1.000)`.
После трёх букв остаётся узкий отрезок `[0.704, 0.741)`.
Любое число из него, например `0.72`, однозначно задаёт строку `cab`.

После каждой буквы её частота увеличивается на 1, поэтому модель подстраивается под конкретный текст.
Например, если буква `e` уже встречалась после `t` много раз, её часть после `t` станет широкой.
Декодер обновляет частоты точно так же, поэтому его модель всегда совпадает с моделью кодировщика.

В программе вместо дробей используются целые границы `low` и `high` на 32 битах.
Когда старшие биты `low` и `high` совпадают, они больше не изменятся, поэтому их сразу выводят в поток.
Это называется ренормализацией и спасает от нехватки точности.
Именно эти выведенные биты и образуют сжатые данные.

Формат сжатых данных простой.

```text
+------------------+-------------------------------------------+
| длина n (4 байта)| арифметический код (сколько получилось)   |
+------------------+-------------------------------------------+
```

Первые 4 байта хранят длину исходной строки `n` в формате little-endian.
Она нужна декодеру, потому что в арифметическом коде нет символа "конец строки".

#### Сложность arithmetic coding order 1

На каждую букву перебираются 26 частот, поэтому время `O(26 * n) = O(n)`.
Память под модель равна `O(1)`, потому что в ней 27 контекстов по 26 частот.
Дополнительно нужно `O(n)` памяти на входную строку и результат.

### 2. Arithmetic coding order 2 (арифметическое кодирование, контекст 2)

#### Идея arithmetic coding order 2

Идея та же, что в первом подходе, но теперь смотрим на две предыдущие буквы.
Пары `th`, `he`, `in`, `er` встречаются в английском очень часто.
Такая пара предсказывает следующую букву лучше, чем одна буква, поэтому сжатие получается плотнее.

#### Как работает arithmetic coding order 2

Контекст - это информация о предыдущих буквах, которую мы используем при выборе частот.
Чем длиннее контекст, тем точнее предсказание, но и тем больше контекстов нужно хранить.

```text
Вид контекста     Номера      Что известно
начало строки     0           ничего
одна буква        1..26       предыдущая буква A
две буквы         27..702     буквы A и B, где B - последняя
```

Всего получается `1 + 26 + 26 * 26 = 703` контекста.
Для двух предыдущих букв `A` и `B` номер контекста считается по формуле `ctx = 27 + A * 26 + B`.
Например, кодируем букву `e` в слове `the`.
Тогда `A = t = 19` и `B = h = 7`, поэтому `ctx = 27 + 19 * 26 + 7 = 528`.
Именно в контексте 528 берутся частоты для выбора части буквы `e`.

Дальше всё устроено как в первом подходе.
Кодировщик сужает общий отрезок, обновляет частоты и выводит совпавшие старшие биты.
Декодер повторяет те же действия и получает те же буквы.
Формат данных такой же: 4 байта длины `n`, затем арифметический код.

#### Сложность arithmetic coding order 2

На каждую букву по-прежнему перебираются 26 частот, поэтому время `O(n)`.
Память под модель равна `O(1)`, так как 703 контекста по 26 частот - это фиксированный размер.
Дополнительно нужно `O(n)` памяти на входную строку и результат.

## Сравнение подходов

| Подход                    | Время | Память | Биты на букву | Сложность кода |
|---------------------------|-------|--------|---------------|----------------|
| Arithmetic coding order 1 | O(n)  | O(n)   | ~3.3-3.6      | средняя        |
| Arithmetic coding order 2 | O(n)  | O(n)   | ~2.9-3.2      | средняя        |

## Что выбрать

- Для простого и надёжного решения достаточно arithmetic coding order 1: он укладывается в лимит с запасом.
- Для лучшего сжатия и большего запаса выбирайте arithmetic coding order 2.
