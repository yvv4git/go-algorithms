# Подходы к задаче "K Divisible Elements Subarrays"

## Суть задачи

Дан массив целых чисел `nums` и два числа `k` и `p`.
Подмассив - это непрерывная часть массива.
Нужно посчитать количество различных подмассивов, в которых не более `k` элементов делятся на `p`.
Два подмассива различны, если у них разная длина или хотя бы один элемент на одинаковой позиции отличается.

Ключевое наблюдение: при движении правой границы вправо число элементов, делящихся на `p`, только растёт.
Поэтому для каждой левой границы можно остановиться, как только счётчик превысил `k`.

Пример: `nums = [2, 3, 3, 2, 2]`, `k = 2`, `p = 2`.
Элементы 2, 2 и 2 делятся на 2, поэтому подмассив `[2, 3, 3, 2]` подходит, а `[2, 3, 3, 2, 2]` нет.
Различных подходящих подмассивов здесь 11.

## Подходы

### 1. Bruteforce (перебор с хеш-таблицей)

#### Идея bruteforce

Перебрать все подмассивы и сложить подходящие в хеш-таблицу, чтобы убрать повторы.

#### Как работает bruteforce

Хеш-таблица - это `map`, которая проверяет наличие ключа за O(1) в среднем.
Для каждой левой границы `left` двигаем правую границу `right` и поддерживаем счётчик `divisible`.
Если `nums[right] % p == 0`, увеличиваем `divisible`.
Когда `divisible > k`, прекращаем перебор для текущей `left`, потому что дальше счётчик только вырастет.
Каждый подходящий подмассив кодируется в строку `key` без неоднозначности: числа записываются через `strconv.AppendInt` и разделяются запятой.
Ключ добавляется в `map distinct`, поэтому одинаковые подмассивы считаются один раз.
Ответ - размер `map distinct`.

#### Сложность bruteforce

Время O(n^3) в худшем случае: всего O(n^2) подмассивов, а кодирование подмассива длины L занимает O(L).
Память O(n^3): в `map` хранятся ключи всех различных подмассивов, а суммарная длина ключей может достигать O(n^3).

### 2. Trie (префиксное дерево)

#### Идея trie

Строить префиксное дерево из значений подмассивов и считать новые вершины.

#### Как работает trie

Trie - это дерево, в котором путь от корня задаёт последовательность значений.
Корень - это пустая вершина: она означает, что мы ещё не выбрали ни одного элемента.
Каждое ребро подписано числом из массива.
Вершина, до которой мы дошли по пути, соответствует подмассиву из чисел на этом пути.
Каждая вершина хранит `map children`, где ключ - значение элемента, а значение - дочерняя вершина.
Для каждой левой границы `left` начинаем с корня `root` и двигаем `right` вправо, поддерживая `divisible`.
Если `nums[right] % p == 0`, увеличиваем `divisible`.
Если `divisible > k`, прекращаем перебор для текущей `left`, потому что дальше счётчик только вырастет.
Значение `nums[right]` вставляется как ребёнок текущей вершины.
Если такого ребёнка не было, создаём новую вершину и увеличиваем `distinct` на 1.
Если ребёнок уже был, такой подмассив уже встречался, и ничего не прибавляем.
Каждая новая вершина соответствует новому различному подмассиву, поэтому ответ равен числу созданных вершин.

Разберём `nums = [2, 3, 3, 2, 2]`, `k = 2`, `p = 2` по шагам.
На 2 делятся числа на позициях 0, 3 и 4.
Просматриваем все левые границы:

- `left = 0`, начинаем с `[2]`: добавляем `[2]`, `[2, 3]`, `[2, 3, 3]`, `[2, 3, 3, 2]`, получаем 4 новые вершины.
- На `[2, 3, 3, 2, 2]` счётчик `divisible` станет равен 3, поэтому для `left = 0` останавливаемся.
- `left = 1`, начинаем с `[3]`: добавляем `[3]`, `[3, 3]`, `[3, 3, 2]`, `[3, 3, 2, 2]`, получаем ещё 4 новые вершины.
- `left = 2`, начинаем с `[3]`: `[3]` уже есть, добавляем только `[3, 2]` и `[3, 2, 2]`, получаем 2 новые вершины.
- `left = 3`, начинаем с `[2]`: `[2]` уже есть, добавляем только `[2, 2]`, получаем 1 новую вершину.
- `left = 4`, начинаем с `[2]`: `[2]` уже есть, новых вершин нет.
- Итого `4 + 4 + 2 + 1 + 0 = 11` различных подмассивов.

Те же 11 подмассивов по длинам:

- длина 1: `[2]`, `[3]` - 2 подмассива;
- длина 2: `[2, 3]`, `[3, 3]`, `[3, 2]`, `[2, 2]` - 4 подмассива;
- длина 3: `[2, 3, 3]`, `[3, 3, 2]`, `[3, 2, 2]` - 3 подмассива;
- длина 4: `[2, 3, 3, 2]`, `[3, 3, 2, 2]` - 2 подмассива;
- длина 5: `[2, 3, 3, 2, 2]` не подходит, в нём три элемента делятся на 2.

Проверка: `2 + 4 + 3 + 2 = 11`.
Всего в массиве 15 подмассивов, полный `[2, 3, 3, 2, 2]` не подходит, поэтому подходящих вхождений 14.
Но `[2]` встречается три раза, а `[3]` два раза, поэтому различных подмассивов `14 - 2 - 1 = 11`.
Теперь вот дерево, в котором ровно 11 вершин, кроме корня.
Справа от каждой вершины записан подмассив, который задаётся путём от корня до этой вершины.

```text
root
|- 2                  [2]
|  |- 3               [2, 3]
|  |  `- 3            [2, 3, 3]
|  |     `- 2         [2, 3, 3, 2]
|  `- 2               [2, 2]
`- 3                  [3]
   |- 3               [3, 3]
   |  `- 2            [3, 3, 2]
   |     `- 2         [3, 3, 2, 2]
   `- 2               [3, 2]
      `- 2            [3, 2, 2]
```

Сравните список по длинам и дерево: это одни и те же 11 подмассивов.
Например, путь `[2, 3, 3]` ведёт в вершину `[2, 3, 3]`, а путь `[3, 2]` ведёт в вершину `[3, 2]`.

#### Сложность trie

Время O(n^2): для каждой из n левых границ просматривается не более n правых границ.
Память O(n^2): в дереве не более O(n^2) вершин, по одной на каждый различный подмассив.

## Сравнение подходов

| Подход     | Время    | Память   | Коллизии | Сложность кода |
|------------|----------|----------|----------|----------------|
| Bruteforce | $O(n^3)$ | $O(n^3)$ | Нет      | Низкая         |
| Trie       | $O(n^2)$ | $O(n^2)$ | Нет      | Средняя        |

## Что выбрать

- При маленьком `n` подойдёт bruteforce: код проще и его легче проверить.
- Для ограничения `n <= 200` оба подхода работают быстро, но trie не копирует подмассивы целиком.
- Если нужен гарантированный O(n^2) по времени, выбирайте trie.
- Хеш-таблица в bruteforce не даёт коллизий в ответе, потому что ключом является полная строка подмассива.
