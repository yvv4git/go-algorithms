# Distributed Key Generation

## Info

DKG - протокол совместной генерации криптографического ключа.
N участников создают общий ключ, и ни один из них не знает его целиком.
Каждый владеет только своей долей, а любые M из N могут подписать или расшифровать.
Схема построена поверх VSS: каждый участник сам является дилером своей доли.

## Joint-Feldman DKG (GJKR)

Протокол Gennaro, Jarecki, Krawczyk, Rabin (1999).
Работает в группе простого порядка `q` по модулю простого `p` с генератором `g`.

### Фаза 1: генерация долей

Каждый участник `i` выбирает многочлен степени `t-1`:

```text
f_i(x) = a_i0 + a_i1·x + ... + a_i,t-1·x^(t-1)
```

Потом он публикует коммитменты к коэффициентам и отправляет доли `f_i(j)` участнику `j` зашифрованно:

```text
C_ik = g^(a_ik) mod p
```

### Фаза 2: верификация

Участник `j` проверяет каждую полученную долю через коммитменты Feldman:

```text
g^s_ij == Π_k C_ik^(j^k) mod p
```

Если проверка не прошла, участник публикует complaint и не участвует в сборке с данными этого дилера.

### Фаза 3: агрегация

```text
PK = Π_i C_i0 = g^Σ_i a_i0
SK = Σ_i a_i0 - никому неизвестен
share_j = Σ_i s_ij
```

Публичный ключ известен всем и позволяет проверять подписи.
Приватный не существует ни у кого в виде одного числа.

## Отличие от VSS

- **VSS** - один дилер делит свой секрет, участники только получают доли
- **DKG** - все участники одновременно дилеры, а общий секрет равен сумме их секретов

## Свойства

- **No trusted dealer** - ключ создаётся только совместно
- **Threshold** - подпись восстанавливается из M долей
- **Robust** - нечестный участник обнаруживается верификацией долей
- **Открытый публичный ключ** - проверка подписи не требует всех участников

## Применение

- **Ethereum 2.0** - группы операторов генерируют ключ валидатора
- **Threshold-кошельки** - транзакцию подписывают M из N устройств
- **Cross-chain мосты** - валидаторы генерируют общий ключ подписи
