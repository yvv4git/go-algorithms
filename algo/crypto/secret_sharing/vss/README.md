# Verifiable Secret Sharing (Feldman)

## Info

VSS - развитие Shamir, где участник может проверить свою долю заранее.
Проверка проходит до того, как соберётся пороговое количество долей.
Схема Feldman (1985) публикует коммитменты к коэффициентам многочлена в группе простого порядка.

## Что это?

Дилер выбирает многочлен по модулю `q`, где `q` - простой порядок группы:

```text
f(x) = S + a_1·x + a_2·x^2 + ... + a_{M-1}·x^(M-1)
```

Участник `i` получает долю `f(i)`, а всем участникам публикуются коммитменты к коэффициентам:

```text
C_k = g^(a_k) mod p
```

Здесь `p` - простое число, а `g` - элемент порядка `q`.

## Проверка доли

```text
g^f(i) == Π_k C_k^(i^k) mod p
```

Левая часть считается из значения доли, правая - из коммитментов.
Если дилер выдал не ту долю, равенство не выполняется и попытка раскрытия отвергается.

## Параметры модуля

- `p` - 1024-битное простое из RFC 3526 (группа 2)
- `q = (p-1)/2` - тоже простое, поэтому `2` порождает подгруппу порядка `q`
- Простое вида `2q+1` называется safe prime: в группе порядка `p` всего один элемент порядка `p`

Демонстрация использует `p` из константы `SafePrimeHex`, порог 2 и 3 участника.

## Feldman и Pedersen

Feldman коммитит коэффициенты в экспоненциальном виде, поэтому публикуется `g^S`.
При достаточно большом модуле это раскрывает один бит секрета через проблему дискретного логарифма.
Pedersen добавляет `h^w` с независимым генератором и делает раскрытие perfect.

## Ограничения

- Вычисления идут в группе порядка `q`, поэтому доли занимают 1023 бита
- Feldman VSS не устраняет утечку `g^S`, для этого нужен Pedersen
- Коммитменты проверяют долю, но не защищают канал доставки от подмены

## Где применяется

- Совместное управление секретами, где участники не доверяют дилеру
- Основа Joint-Feldman DKG - генерации общего ключа без дилера
- Протоколы MPC, где дилер может вести себя нечестно
