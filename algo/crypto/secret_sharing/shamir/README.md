# Shamir Secret Sharing

## Info

Shamir Secret Sharing (SSS, 1979) - наиболее распространённый метод разделения секрета.
Секрет делится на N частей (shares), любые M из N восстанавливают оригинал, а M-1 не дают никакой информации.
Основан на полиномиальной интерполяции Лагранжа над конечным полем.

## Что это?

Схема разделения секрета: вместо хранения секрета целиком у одной стороны он разбивается на N долей.
Никто не может получить секрет в одиночку.

Свойства схемы:

- **Threshold (порог)** - задаётся число M: любые M из N долей дают секрет, а M-1 не дают ничего
- **Perfect secrecy** - M-1 долей не дают никакой информации о секрете, даже вероятностно
- **Компактность** - каждая доля того же размера, что и сам секрет
- **Линейность** - доли складываются: `share(a + b) = share(a) + share(b)`

## Принцип работы

### Разделение (Dealer)

Секрет S кодируется как свободный член полинома степени M-1:

```text
f(x) = S + a_1·x + a_2·x^2 + ... + a_{M-1}·x^(M-1)

    a_i - случайные коэффициенты
    M   - порог (threshold)
```

Коэффициенты `a_i` выбираются случайно и держатся в секрете: именно их случайность и даёт perfect secrecy.

Каждая доля - это значение полинома в конкретной точке:

```text
share_1 = (1, f(1))
share_2 = (2, f(2))
...
share_N = (N, f(N))
```

Дилер отдаёт участнику i пару `(i, f(i))` - координату и значение.

### Восстановление (Combine)

Любые M точек достаточны, чтобы восстановить полином через интерполяцию Лагранжа:

```text
f(x) = Σ y_i · L_i(x)   для i = 1..M

    L_i(x) = Π (x - x_j) / (x_i - x_j)   для всех j ≠ i
```

Секрет - это значение полинома в нуле:

```text
S = f(0)
```

Деление на `(x_i - x_j)` требует обратимости ненулевых элементов, поэтому вычисления идут в конечном поле.
Это mod P для простого P, либо GF(2^k) для бинарных данных.

## Пример

Разделим секрет `S = 13` на 3 доли с порогом `M = 2`.
Степень полинома = M-1 = 1, значит есть один случайный коэффициент `a_1 = 4`:

```text
f(x) = 13 + 4·x

share_1 = (1, 17)
share_2 = (2, 21)
share_3 = (3, 25)
```

### Восстановление из долей 2 и 3

Порог достигнут, полином восстанавливается интерполяцией Лагранжа:

```text
L_1(0) = (0 - x_2) / (x_1 - x_2) = (0 - 3) / (2 - 3) = 3
L_2(0) = (0 - x_1) / (x_2 - x_1) = (0 - 2) / (3 - 2) = -2

S = y_1·L_1(0) + y_2·L_2(0) = 21·3 + 25·(-2) = 63 - 50 = 13
```

### Почему одна доля бесполезна

Возьмём только долю `(2, 21)`.
Для любого возможного `S` есть полином `f(x) = S + (21 - S)/2 · x`, дающий ровно такую же долю.
Значит, одну долю не сужает множество возможных `S`.
Информации о секрете ровно ноль.

## Где применяется

- **Seed phrase backup** - кошельки делят seed-фразу на M из N частей
- **Multisig** - Shamir в сочетании с ECDSA (Taproot, Schnorr)
- **DKG** - Distributed Key Generation, когда доли собирают несколько сторон
- **Validator keys** - распределённое хранение ключей валидаторов
- **MPC** - входные данные в многосторонние вычисления

## Ограничения

- **Нет верификации** - дилер может раздать некорректные доли, и участники об этом не узнают
- **Одноразовость** - при восстановлении секрет раскрывается всем участникам
- **Статичность** - нельзя добавить или удалить участника без пересоздания схемы
